# agentic-plugin docs

## Reference

- `architecture.md`: how the plugin, the supervisor and the process keeper fit together: each layer's process, what it owns, reads and writes, the plan document a queue entry names among the plugin's reads, the boot-time data flow, the keeper's roster, env file, policy and state files, the fleet reading the coordinator persona's plugin runs over the keeper's own state files and the restart request it writes into another persona's run directory, the supervisor self-heal paths the keeper depends on, the text those layers inject into a child session with the ledger and duplicate test that guard its size, the external integrations, and the failure modes by layer. `README.md` at the repository root is the operator-facing reference each section points back to.

## Active plans

- `plans/agent_persona_no-goal-idle_v1.md`: No-goal idle (an error streak on a persona with no active goal node is logged and opens no ask, so a persona that holds no standing goal sits idle between asks instead of escalating a question nobody can act on).
- `plans/agent_persona_goal-tree-curation_v1.md`: Goal tree curation (a turn that works without a goal leaves one collapsed decision-log line and never replaces the tree, `goal_done` completes any finished entry by name, `goal_create` refuses to replace an unfinished tree without `replace: true` and keeps a replaced tree in a history file, and one refused tool registration no longer costs a session its persona claim and stored tree). Ready. Runs after the supervisor-gaps plan merges (the plan-health plan is complete), because it edits the same regions of `hooks/index.ts` and `bin/supervise.sh`.
- `plans/agent_persona_keeper-park_v1.md`: Keeper park (the shutdown tool takes a park option, a parked supervisor exits 6 where a stopped one exits 0, the process keeper writes a park marker its next start clears and launches on while a hold marker still waits for a hand release, and the fleet reading reports a parked persona as held with a reason naming the park). Ready. Runs after the supervisor-gaps and goal-tree-curation plans merge, because it edits the same stop paths, the same launch path and the same description ledger.
- `plans/agent_persona_goal-levels_v1.md`: Goal levels (a self-review finding leaves the persona that found it as a record to the coordinator persona and never becomes a goal in its own tree, a long-term goal is a list in the persona's store that can never be the active work, an idle persona holding one is asked once a day for a proposal that takes the same road, the tools that start a new effort refuse in any turn the operator or the coordinator persona did not start, and a top goal whose work is all done completes without the planner being asked). Ready. Runs after the plan-health, goal-tree-curation and keeper-park plans merge, because it edits the same goal tools, the same `GoalNode` shape and the same description ledger.
- `archive/agent_persona_dead-claim-release_v1.md`: Dead claim release. Abandoned 2026-09-21 before any section ran: the claude-kit repository retired the heavy-process claim everywhere, so there is no claim for a supervisor to free. The steward's seat name still needs no change in this repository: the kit's fleet coordinator seat plan lets the coordinator seat be taken under the roster name a fleet launches its coordinating persona with.
- `plans/agent_persona_supervisor-peer_v1.md`: Supervisor as peer (the supervisor judges its child gone only on five silent signals together and after one final ask, never restarts a child whose output names a usage limit, turns off the harness usage-limit pause for supervised children, puts a deliberate shutdown to the child through a run-directory mailbox it answers at a boundary, launches the child under a holder process so it outlives the supervisor, adopts a live child at start, and keeps the kill as the last rung). Ready. Its close condition is met now the steward-architect plan has closed, and execution still waits on the operator's own word, which its Dispatch Authorization requires separately.
- `plans/agent_persona_deferred-gate-run_v1.md`: Deferred gate run (the runs that hold the box, the live suites and the driven supervisor suite, are deferred from every queued plan to one whole gate after the last of them merges, with each red traced to its plan and fixed or filed; it owns the gate policy the four plans cite). Ready, parked last.

## Archived plans

- `archive/agent_persona_task-password-logon_v1.md`: Task password logon (every `AgentPersona-<name>` scheduled task is registered with the Password logon type instead of S4U, the registration script takes the account credential at a `Get-Credential` prompt and never on the command line or from a file, and a task registered this way reads the account's user-scope DPAPI key, so a persona's git reaches the credential stores the operator's own session reads). Complete on the `task-password-logon-build` branch; the most recent plan. `README.md` under Process keeper and `architecture.md` under the boot data flow are the operator-facing references. The re-registration on the fleet box is machine state the plan's Chapter 2 records, and a password change on that account stops every task until the script runs again.
- `archive/agent_persona_supervisor-gaps_v1.md`: Supervisor gaps (the coordinator persona restarts another persona's child through a request file in that persona's run directory, a requested restart waits for a running turn to end before any signal is sent, and a keeper that finds a live supervisor for its persona adopts it and launches nothing beside it). Complete on the `supervisor-gaps-build` branch. `README.md` under `fleet_restart`, Stop Phases and Process keeper is the operator-facing reference, and `architecture.md` states the request file in the layer table. Two operator checks and one open decision, the shutdown request dropped during the patient wait, are on `backlog.md`.
- `archive/agent_persona_plan-health-from-the-record_v1.md`: Plan health from the record (a queue entry that carries a plan document is judged from that document and from the first line of the worker's own closing text, carries no round budget, and is never scored on a turn the operator or the coordinator persona started; three Jev questions about plan health are asked in shadow and journaled, and nothing acts on them). Complete on the `plan-health-build` branch. `README.md` under "Plan entries: judged from the record" is the operator-facing reference, and `architecture.md` states the plan document as a record the plugin reads. A blocked lead lifts on a working turn, on `goal_resume`, or once an ask on the entry closes after it; a waiting lead holds an hour. Its two operator checks are on `backlog.md`.
- `archive/agent_persona_decision-seam_v1.md`: Decision seam (one module through which the plugin's closed questions can be put to Jev, the TypeSafe classifier service; the four existing closed questions run in shadow beside Haiku, which still makes every decision; question wording is versioned data with an override layer outside the repository; every shadow answer lands in a local append-only journal with its probabilities, its input and output token counts and later its outcome). Complete on the `decision-seam-build` branch. A tree carrying `hooks/decision-seam.ts` has it; a tree without that file does not. `README.md` under Decision seam is the operator-facing reference, and `architecture.md` states the seam's place in the plugin. Nothing acts on a Jev answer: a branch whose outcome depends on one is a defect, and a suite instrument checks it. Joining the outcome back is wired for one of the four sites and not the other three, which the plan records as a measurement gap for a later plan. Updating the installed plugin copy and relaunching each supervisor is the operator's own act, listed under its Operator Verification.
- `archive/agent_persona_lean-injection_v1.md`: Lean injection (every prompt the plugin or supervisor writes into a session, and every tool description, says only what its reader cannot already know and points at the owner for the rest, with a duplicate-sentence test and a size ledger as the guard). Complete on the `lean-injection` branch. What it built: the startup message and the recurring prompts trimmed against their owners, the plugin’s shared reply preamble deleted, the fourteen tool descriptions cut to their contracts, and `.kit/injection-ledger.mjs` with `.kit/injection-duplicate-test.mjs` as the guard. `architecture.md` states the guard and its declared coverage bounds. Its one open question, whether `fleet_status` should register for the coordinator alone rather than every session, is the operator’s and is recorded in the plan.
