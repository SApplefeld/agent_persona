# agentic-plugin docs

## Reference

- `architecture.md`: how the plugin, the supervisor and the process keeper fit together: each layer's process, what it owns and writes, the boot-time data flow, the keeper's roster, env file, policy and state files, the fleet reading the coordinator persona's plugin runs over the keeper's own state files, the supervisor self-heal paths the keeper depends on, the external integrations, and the failure modes by layer. `README.md` at the repository root is the operator-facing reference each section points back to.

## Active plans

- `plans/agent_persona_supervisor-peer_v1.md`: Supervisor as peer (the supervisor judges its child gone only on five silent signals together and after one final ask, never restarts a child whose output names a usage limit, turns off the harness usage-limit pause for supervised children, puts a deliberate shutdown to the child through a run-directory mailbox it answers at a boundary, launches the child under a holder process so it outlives the supervisor, adopts a live child at start, and keeps the kill as the last rung). Ready. Its close condition is met now the steward-architect plan has closed, and execution still waits on the operator's own word, which its Dispatch Authorization requires separately.
- `plans/agent_persona_lean-injection_v1.md`: Lean injection (every prompt the plugin or supervisor writes into a session, and every tool description, says only what its reader cannot already know and points at the owner for the rest, with a duplicate-sentence test and a size ledger as the guard). Ready, next in the running order and ahead of the supervisor-peer plan. Both plans it waited on have closed: the steward-architect plan merged as pull request 49, and the context-budget-removal plan is archived.
- `plans/agent_persona_deferred-gate-run_v1.md`: Deferred gate run (the runs that hold the box, the live suites and the driven supervisor suite, are deferred from every queued plan to one whole gate after the last of them merges, with each red traced to its plan and fixed or filed; it owns the gate policy the four plans cite). Ready, parked last.
- `plans/agent_persona_decision-seam_v1.md`: Decision seam (one module through which the plugin's closed questions can be put to Jev, the TypeSafe classifier service; the four existing closed questions run in shadow beside Haiku, which still makes every decision; question wording is versioned data with an override layer outside the repository; every shadow answer lands in a local append-only journal with its probabilities, token count and later outcome). Ready. Outside the armed queue, and execution waits on the operator arming it by name.

- `archive/agent_persona_steward-architect_v1.md`: Steward and architect (the Fable coordinator persona split into a Sonnet steward that keeps the fleet running, holds the kit Coordinator seat and wakes the designer, and a Fable architect with no home repository that does design work when asked; the steward is woken by a plugin-side fleet watcher rather than by a habit in its own instruction). Complete. The cutover onto the new roster is the operator's own procedure and is written in the root `README.md`, and the machine is not cut over yet.
- `archive/agent_persona_context-budget-removal_v1.md`: Context-budget monitor removal (the plugin no longer estimates how full a session's context window is, logs no crossing and writes no close-out turn into the conversation, and the supervisor no longer restarts a child on that estimate; context is left to the harness's own compaction and the kit's gate, and the coordinator's compaction-boundary sentence in the priming turn stays). Complete. Its deferred suites run under `plans/agent_persona_deferred-gate-run_v1.md`, and updating the installed plugin copy and relaunching each supervisor is the operator's own act, listed under its Operator Verification.
- `archive/agent_persona_drop-doorbell_v1.md`: Drop the doorbell (the plugin registers no `session.receive` hook, so a message one persona session sends another through `SendMessage` reaches the receiving model as the harness delivers it, under every arming). Complete; the most recent plan. The live suite `.kit/live-operator-test.sh` was not run for it, and pulling the runtime checkout and relaunching each persona is the operator's own act, listed under its Operator Verification.
