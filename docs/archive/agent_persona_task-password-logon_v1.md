# Task password logon

Status: Complete
Commit Model: Branch-and-PR
Created: 2026-09-22

## Goal

When this is done, every `AgentPersona-<name>` scheduled task runs under a logon that unlocks the operator account's DPAPI key, so a persona's git can read Windows Credential Manager, Git Credential Manager's store and the Azure CLI token cache exactly as the operator's own interactive session does. It matters because the tasks today use an S4U logon, under which user-scope DPAPI returns access denied, so no persona can authenticate to GitHub or Azure DevOps and every commit model that pushes is dead on this box.

## Intent

The operator's frame: the headless sessions need the same git access through Windows Credential Manager that the interactive session has. The root cause is the logon type, not the store. Windows' own definition of the S4U logon says no password is stored and there is no access to encrypted files, and a probe task on ASR-CLAUDE on 2026-09-22 confirmed user-scope DPAPI fails under it while machine-scope DPAPI works. The operator chose the stored-password logon over a machine-scope secret store on 2026-09-22, because it is the literal ask, fixes GitHub and Azure DevOps together, and its one cost, re-registration after a password change, is the operator's to control on a fleet box.

Done means three things. The registration script registers and updates tasks with the Password logon type, taking the credential at the prompt and never on the command line or in a file. The docs that describe the S4U choice describe the new one. And a task registered the new way is observed reading user-scope DPAPI on this box.

Done does not need: a fallback to S4U when no credential is given, a credential read from a file or an environment variable, a read-back check inside the registration script, or the channel broker's task changing, since the broker needs no DPAPI.

Alternatives refused:
- A GitHub App helper and a service-principal secret under machine-scope DPAPI, keeping S4U: refused by the operator on 2026-09-22 in favour of the smaller change. Recorded as the path to take if a stored password later becomes unacceptable.
- Git Credential Manager's plaintext store: a token on disk behind an ACL alone, for no gain over the stored password.

## Section 1: the credential parameter

Model: fable, inline. `bin/Register-PersonaTasks.ps1` gains `-Credential`, a `pscredential`. The script body prompts with `Get-Credential` for `-User` when the parameter is unbound, the run is not `-WhatIf`, and the session is elevated, so an unelevated run still meets the elevation refusal first and a `-WhatIf` run never prompts. `Get-PersonaTaskDefinitions` builds the principal with the Password logon type at RunLevel Limited, so the printed block under `-WhatIf` reads `logon: Password`. `Register-PersonaTasks` takes `-Credential` and refuses, naming the parameter, when a write to an enabled entry is reached without one or with one whose user name is not `-User`. The register path passes `-User`, the credential's password and the definition's run level; the update path passes `-User` and the password, since `Set-ScheduledTask` offers no run level in that parameter set and the existing task keeps its own. `.kit/keeper-register-test.mjs` pins `logon: Password` on the printed block, passes a scratch credential on every case that reaches a write, records the user and run level the stubs receive, pins that the password never reaches stdout, and pins the refusal of a missing credential and of a mismatched user name. Docs: the README's Registering the tasks and environment-file paragraphs, the trust-boundary sentence and the stop paragraph, `docs/architecture.md`'s boot step, builder sentence, resource list and stop paragraph, and the backlog's security-model entry, each rewritten for the new logon.

Acceptance: `node .kit/keeper-register-test.mjs` exits 0 with the new cases counted, against a baseline of 114 passed, 0 failed, exit 0 on `d1ff322`. The real script under `-WhatIf` against `D:\personas\fleet.json` prints `logon: Password` on every block, exit 0.

## Section 2: re-registration on ASR-CLAUDE

Machine state, operator-run. Elevation from a session is unreliable on this box, so a script under `D:\Temp` with a transcript runs the registration with the prompt, prints every task's logon type and run level read back from the scheduler, registers a throwaway task under the same credential that runs the DPAPI probe, reads its result, and deletes it. The operator then signs Git Credential Manager in to GitHub once, since this box holds no GitHub credential yet. The running persona instances keep their S4U logon until the next boot or restart.

Acceptance: the read-back lists eleven tasks at `Password` and `Limited`, the probe's result file reads `DPAPI user-scope: OK`, and `git credential fill` for github.com resolves non-interactively as LocalAdmin.
