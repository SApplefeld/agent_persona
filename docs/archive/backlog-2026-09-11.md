### Goaltree planner variance (Round 35, BL1)

**Status:** Resolved on 2026-09-11 (commit `a0cb72d`)

**Issue:** The goaltree suite asserted an exact 12-step sequence that depended on the planner returning exactly the roadmap's 3 items. On 2026-09-08 the planner returned 4 plans (one extra "Verify Syllable Counts") against a 3-item roadmap, producing a red run. Rerun at the same commit passed with 3 plans.

**Fix:**
1. **Derived expectation:** `.kit/assert-decisions.js` now reads `.kit/roadmap-test.md` and counts numbered items to derive the expected plan count, instead of hardcoding 3. The assertion now checks that the planner created exactly that many plans.
2. **Prompt hardening:** `hooks/index.ts:1398` now tells the planner: "When a roadmap is provided, produce exactly one plan per numbered roadmap item." This reduces the chance of variance.
3. **Variance flagging:** If the planner still returns a different count, the assertion logs `planner_variance flagged` (chose "flagged" over "trimmed" for transparency, so the operator can investigate why the planner returned an unexpected count).

**Proof:** Two-suite green run at `20260911T053426Z` (goaltree, goaltree-stall), both `script_exit=0`, engine 2.1.268. The assert log reads: "OK: goaltree: planner created exactly the roadmap's plan count."
